# RL Puzzle Solver

Interactive web application where reinforcement-learning agents learn to solve a
**3×3×3 Rubik's Cube** and a **Megaminx** (regular dodecahedron). Built for the
*Stochastic Processes* module (M2IA). The interface is in French; code, comments
and this README are in English.

The whole project models each puzzle as an explicit **Markov Decision Process**
(states, actions, stochastic transitions, reward, discount) and compares three
solvers:

| Agent | Idea |
| --- | --- |
| **Q-learning** | Tabular temporal-difference learning with ε-greedy exploration |
| **Double Q-learning** | Two value tables to remove the max operator's overestimation bias |
| **MDP (value iteration)** | Breadth-first state graph + exact value iteration |

## Quick start

```bash
npm install
npm run dev        # development server (http://localhost:5173)
npm run build      # type-check + production build into dist/
npm run preview    # serve the production build
npm test           # unit tests (engine + agents)
npm run bench      # regenerate src/data/results.json (real measurements)
```

Node 18+ is required.

## Modelling

- **States** — one colour configuration. Cube: 54 stickers; Megaminx: 132
  stickers (12 pentagonal faces × 11 pieces).
- **Actions** — cube: 12 quarter turns `[U, U', D, D', L, L', R, R', F, F', B, B']`;
  Megaminx: 24 face rotations (12 faces × {+72°, −72°}, `F0, F0', F1, F1', …`),
  stored in inverse pairs.
- **Transitions** — deterministic rotation, except with probability `p` (slip) a
  uniformly random action is executed instead. The process is therefore genuinely
  stochastic.
- **Reward** — `-1` per move, `0` at the solved (absorbing) state; discount `γ`.
- **Learning taps** — pessimistic initialisation, retrospective replay of each
  scramble backwards, and a self-paced curriculum that only raises the scramble
  depth once the success rate exceeds 95 % (measured at the current level).

Default hyper-parameters: `α = 0.5`, `γ = 0.95`, `p = 0.05`, `init = −15`,
`maxStates = 1 000 000`. Per puzzle: cube `maxDepth = 5`, `ε: 0.3 → 0.15`,
episode length `3·d + 6`; Megaminx `maxDepth = 3` (Q/DQ) or `4` (MDP),
`ε: 0.2 → 0.2`, episode length `1·d + 3`.

## Measured results

Produced by `npm run bench` (seed 12345, 80 trials per cell) and shown in-app from
`src/data/results.json` — never hard-coded:

| Puzzle | Depth | Q-learning | Double Q | MDP |
| --- | --- | --- | --- | --- |
| Cube 3×3×3 | 4 | 100 % | 100 % | 100 % |
| Cube 3×3×3 | 5 | 66 % | 57 % | 100 % |
| Megaminx | 3 | 96 % | 95 % | 100 % |
| Megaminx | 4 | — | — | 100 % |

The Megaminx MDP graph has exactly **6 641 states at depth 3** and **96 785 states
up to depth 4** (17 value iterations), matching the reference engine.

**Fundamental limit.** The 3×3×3 cube has ≈ 4.33·10¹⁹ states and the Megaminx
≈ 10⁶⁸. Tabular Q-learning is therefore reliable only up to **4 moves** on the
cube and **3 moves** on the Megaminx; beyond that the table grows faster than the
memory cap. The app states this explicitly and the MDP (the exact solver) is used
to illustrate perfect performance at larger depths. Deep Q-Networks are mentioned
as an outlook only, and are **not** implemented.

## How it works in the browser

Training runs inside a **Web Worker** (`src/agents/worker.ts`) so the interface
never blocks. The main thread talks to it through `SolverClient`
(`src/agents/client.ts`) using a small request/response protocol. The main
thread owns the puzzle animation (Three.js for the cube and the Megaminx) and
replays the solution returned by the worker.
