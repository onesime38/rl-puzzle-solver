## 4. Modelling (follow exactly)
**Cube 3×3×3**
- State: 54 stickers, colours 0–5 (`Uint8Array(54)`, hash key = 54-character string).
- Actions: **12 quarter turns**: U, U', D, D', L, L', R, R', F, F', B, B'. Actions are stored in pairs (a, a^1 = inverse), which simplifies scrambling without immediate undo and retrospective replay.
- Each move is a precomputed permutation of the 54 positions. Tests: `inverse(a)` cancels `a`; four identical quarter turns = identity; `(R U R' U')` repeated 6 times = identity; the 3D view state always equals the logical state.

**Hexagon puzzle** (same definition as the prototype)
- 12 cells: outer ring (indices 0–5) and inner ring (6–11), 6 colours; solved state = cells i and 6+i have colour i.
- 8 actions: rotation of the outer ring, of the inner ring, of half-hexagon S1 (cycle 0,1,2,8,7,6) and of half-hexagon S2 (cycle 3,4,5,11,10,9), each in both directions.

**Common MDP**
- S: configurations. A: rotations. Reward −1 per move, 0 at the solved state (absorbing). Discount γ.
- **Stochastic transition**: with probability p ("slip") the executed action is replaced by a uniformly random action. This makes the process genuinely Markovian and stochastic.

## 5. Algorithms (tabular implementations)
1. **Q-learning**: `Q(s,a) ← Q(s,a) + α [r + γ max_a' Q(s',a') − Q(s,a)]`, ε-greedy policy.
2. **Double Q-learning**: two tables QA and QB; at each update a fair coin chooses which table to update; the action is selected by the updated table and evaluated by the other; ε-greedy on QA+QB.
3. **Markov process (MDP)**: explicit state graph built by BFS from the solved state up to depth D, then **value iteration** `V(s) = max_a Σ P(s'|s,a)[r + γ V(s')]` until the maximum change is below 1e-6. Display the number of states, the number of iterations and the convergence curve of the maximum change.

## 6. Fundamental limit of the 3×3×3 (handle it honestly)
The 3×3×3 has 4.3·10¹⁹ states, so a complete Q-table is impossible. Use **bounded curriculum learning**:
- Train and evaluate on scrambles of depth 1, then 2, then 3… up to `maxDepth` (default 5, adjustable up to 6).
- Orders of magnitude in the quarter-turn metric: number of states at exact distance d = 1, 12, 114, 1068, 10011, 93840, 878880 (d = 0…6). Up to d = 5 there are about 105,000 states; up to d = 6 about 1 million.
- Memory: avoid millions of small objects. Store Q-values in a large `Float32Array` plus a `Map<string, number>` from state key to row index. Add a memory cap and stop training cleanly when it is reached.
- The UI must state clearly: "Le cube est résolu pour des mélanges jusqu'à N coups (limite du Q-learning tabulaire)", and the Algorithmes page explains why. The scramble slider is limited to `maxDepth`.
- Do not implement Deep Q-Networks; mention them as a perspective only.

## 7. Lessons from the prototype (essential, otherwise learning fails)
Naive Q-learning gets **stuck at depth 3**. Three fixes made it converge:
1. **Pessimistic initialisation** of Q-values to **−15** (not 0). With 0 and reward −1, never-seen states look better than states close to the goal, and the greedy policy gets lost.
2. **Retrospective replay**: at each episode, generate a scramble of d moves and replay it backwards (real transitions `s_i → s_{i−1}` using the inverse action), applying the same Q-learning / Double Q-learning updates. This propagates values quickly from the solved state.
3. **Curriculum**: the level (scramble depth) increases when the success rate exceeds 95 % on 80 test scrambles.

Parameters that worked: α = 0.5; γ = 0.95; ε = 0.3; p = 0.05; exploration episodes of length 3d + 6; scrambles without immediate undo. Measured on the prototype at depth 5: Q-learning and Double Q-learning reach 97–99 % after about 150,000 episodes (a few seconds), the MDP reaches 100 %. You must obtain results of the same order on the 3×3×3 at depth 4 or 5. If not, tune (more episodes, α, ε) and document every change.

Solving: at each step choose the action with the highest value among those that do not return to an already visited state (loop avoidance), with a maximum of 40 moves.
